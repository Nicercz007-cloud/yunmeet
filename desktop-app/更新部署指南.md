# 云聚桌面版 · 更新装置部署指南（帽子云 + GitHub 双通道）

桌面版里装了和物光口袋同一套思路的"更新装置"，只是搬到了 Windows 上：

| 半边 | 在哪 | 干什么 |
|---|---|---|
| **发放端** | 静态托管（帽子云 或 GitHub Releases） | 告诉软件"现在最新是几版、去哪儿下" |
| **接收端** | 桌面软件里（electron-updater） | 启动时检查 → 后台静默下载 → 弹窗问"立即重启吗" → 重启即新版 |

**以后每发一版，本质上只换两个文件：`latest.yml` + 新的安装包 exe。**

---

## 一、发放端二选一

### 方案 A：帽子云（推荐，和物光口袋完全同款，国内下载快）

1. 在 GitHub 建一个新仓库，比如 `yunmeet-upd`（Public/Private 都行）
2. 把 `desktop-app/dist/` 里的 **`latest.yml` 和 `YunMeet-Setup-1.0.0.exe`** 一起传到仓库根目录
   （顺手传一份 `index.html` 当下载页也行，见 `upd-kit/`）
3. 打开 <https://dash.maoziyun.com/login> → 创建应用 → 授权并选中该仓库 → 分支 main → 构建配置留空
4. 构建完成后得到域名，形如 `https://xxxxxx.maoziyun.com`
5. 浏览器验证：<https://xxxxxx.maoziyun.com/latest.yml> 应显示一段含 `version:` 的文本
6. **把该域名填进 `desktop-app/main.js` 顶部的 `MAOZI_UPDATE_URL`**（记得带结尾的 `/`），然后 `npm run dist` 重新打包一次——之后所有用户就从这个域名拉更新了

### 方案 B：GitHub Releases（零手工，但国内直连可能慢）

发新版的两种做法：

**自动（推荐给会用命令行的场景）：**

```bash
# 先设置个人访问令牌（需 repo 权限）：https://github.com/settings/tokens
set GH_TOKEN=ghp_xxxx
npm run dist -- --publish always
```

**手动（不想配 token）：**

1. 打开 <https://github.com/Nicercz007-cloud/yunmeet/releases> → **Draft a new release**
2. Tag 填 `v1.0.0`（必须和 package.json 的 version 一致，前缀 v）
3. 把 `dist/YunMeet-Setup-1.0.0.exe` 和 `dist/latest.yml` 两个文件拖进附件
4. 点 **Publish release**

桌面软件启动时就会从 Releases 拉到 `latest.yml` 并完成更新。

---

## 二、发版流程（每次照抄）

1. 改 `desktop-app/package.json` 里的 `version`（必须比上一版**大**，如 1.0.0 → 1.0.1）
2. 如果 `yunmeet.html` 有更新：直接改根目录的原文件即可，打包时会自动带上（不用动 desktop-app）
3. `npm run dist`
4. 把 `dist/latest.yml` 和 `dist/YunMeet-Setup-新版本号.exe` 传到发放端（帽子云就"只换两个文件"）
5. 已装的用户下次启动软件就会收到更新弹窗

---

## 三、注意事项

- **SmartScreen 提示**：安装包没有买代码签名证书，第一次安装时 Windows 可能蓝屏提示"已保护你的电脑"——点 **更多信息 → 仍要运行** 即可。这是所有免费分发软件的正常现象（物光口袋的 apk 也一样）。
- **版本号必须严格递增**，否则更新器认为"已是最新"。
- `latest.yml` 和 exe 必须**同目录、同版本**，版本对不上会校验失败。
- 更新日志：改 latest.yml 里的 `releaseName` 可以让弹窗显示版本名；想给用户看更详细的更新说明，发布到 GitHub Releases 的正文里写即可。
- 参会者不需要装新版也能开会——桌面版和网页版（GitHub Pages）会议号互通，只要 6 位号一样就进同一个会。
